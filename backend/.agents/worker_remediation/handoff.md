# Handoff Report: Defect Remediation for QuestionType.SCORE Evaluation

## 1. Observation
- **TEST_READY.md § 6**:
  > "1. Defect in `ScoringEngine._extract_score_value` / `SyntheticJevGateway` for `QuestionType.SCORE` questions:
  > - Observation: In `app/gateways/synthetic.py` lines 337-347, `SyntheticJevGateway` populates findings for SCORE questions as:
  >   `{"type": "score", "choice": choice, "probabilities": ...}`
  > - However, in `app/services/scoring.py` lines 103-106, `ScoringEngine._extract_score_value` only inspects:
  >   `raw.get("score") or raw.get("level") or raw.get("value")`
  >   It does not check `raw.get("choice")`.
  > - Impact: Any SCORE-type question graded by the default `SyntheticJevGateway` ... produces `None` in `_score_single_question`, resulting in a subscore of `0.0` unless explicitly provided as `{ "level": ... }` or `{ "score": ... }`."
- **app/services/scoring.py (lines 102-106)**:
  `_extract_score_value` previously returned `raw.get("score") or raw.get("level") or raw.get("value")`, missing `"choice"`.
- **app/gateways/synthetic.py (lines 337-347)**:
  `results[q_id]` only included `"type": "score"`, `"choice": choice`, `"probabilities": ...`, missing `"level": choice`.
- **Test execution commands and outputs**:
  - `uv run pytest`: 163 passed in 0.78s
  - `uv run ruff check .`: All checks passed!
  - `uv run ruff format --check .`: 122 files already formatted

## 2. Logic Chain
1. **Observation 1 & 2**: `ScoringEngine._extract_score_value` only checked keys `"score"`, `"level"`, and `"value"`. When findings generated by `SyntheticJevGateway` contained only `"choice"`, `_extract_score_value` evaluated to `None`.
2. **Observation 3**: In `SyntheticJevGateway`, SCORE-type results populated `"choice"` but omitted `"level"`.
3. **Step 1 Fix**: In `app/services/scoring.py`, updating `_extract_score_value(raw: Any) -> str | None` to inspect `raw.get("score") or raw.get("level") or raw.get("value") or raw.get("choice")` guarantees that any representation providing `"choice"`, `"level"`, `"score"`, or `"value"` resolves to the target string.
4. **Step 2 Fix**: In `app/gateways/synthetic.py`, adding `"level": choice` alongside `"choice": choice` ensures `SyntheticJevGateway` fulfills both schema expectations concurrently without breaking legacy callers expecting `"choice"`.
5. **Step 3 Tests**: In `tests/unit/test_scoring_engine.py`, Section 6 adds 28 test cases across `test_score_question_representation_formats`, `test_extract_score_value_direct`, and `test_synthetic_jev_gateway_score_question_integration`.
6. **Observation 4**: Executing `uv run pytest` yielded 163 passing tests with zero failures, and `ruff` checks passed cleanly.

## 3. Caveats
No caveats. The fix is strictly backward-compatible, adheres to all interface contracts, and requires no external network or API keys.

## 4. Conclusion
The defect documented in TEST_READY.md § 6 is fully remediated. Both `ScoringEngine._extract_score_value` and `SyntheticJevGateway` now correctly support SCORE questions across all representation formats (`"choice"`, `"level"`, `"score"`, and `"value"`), with zero regressions across the entire 163-test suite.
