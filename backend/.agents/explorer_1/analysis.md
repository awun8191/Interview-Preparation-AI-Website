## 1. Executive Summary

This investigation surveys the current state of the backend codebase, monorepo context, runtime environment, and architectural requirements for **The-Plan-Software** communication coaching platform.

### Core Survey Findings:
1. **Greenfield Status:** The `backend/` directory is an uncommitted initial scaffold generated by `uv init`. It contains only a skeleton `pyproject.toml` with zero dependencies, an empty `README.md`, a 3-line `src/backend/__init__.py` printing "Hello from backend!", and a virtual environment with no application packages installed.
2. **Runtime & Toolchain Alignment:** Python $\ge 3.13$ is pinned via `.python-version` (containing `3.13`) and supported by `cpython-3.13.13` pre-installed in the local `uv` environment (`~/.local/share/uv/python/cpython-3.13-linux-x86_64-gnu/bin/python3.13`). `uv 0.12.5` is installed and ready at `/home/nasbombz/.local/bin/uv`.
3. **Monorepo Architecture & Contracts:** The monorepo establishes strict conventions in `CLAUDE.md` and `AGENTS.md`. Key backend mandates include:
   - Execution command: `uv run uvicorn app.main:app --host 127.0.0.1 --port 8017 --reload`
   - Test command: `uv run pytest`
   - Lint & format command: `uv run ruff check .` and `uv run ruff format --check .`
   - Sub-second latency budget ($< 1.0\text{s}$) across the cognitive pipeline: Audio $\rightarrow$ Groq Whisper STT ($\sim 350\text{ms}$) $\rightarrow$ Jev System One ($\sim 200\text{ms}$) $\rightarrow$ Deterministic Scorecard ($\sim 5\text{ms}$).
   - Zero hallucinated scores and strict adherence to the **Balanced Impact Rule** (full credit for both quantitative data and qualitative/operational outcomes).
   - Standardized non-2xx error envelope: `{"error": {"code": "...", "message": "...", "retryable": bool}, "request_id": "..."}`.
4. **Rich Framework Specifications:** The `docs/frameworks/` directory contains complete specifications and Jev wire catalogs for all 11 target communication frameworks (STAR, CARL, PAR, SCQA, SBI, Radical Candor, STATE, Gottman, Voss, Sparkline, Monroe).
5. **Architectural Recommendation:** Migrate from the scaffolded `src/backend` layout to a standard top-level `app/` structure (`backend/app/...`) packaged cleanly via `hatchling` in `pyproject.toml`. This directly satisfies the `uvicorn app.main:app` entry point, supports dependency injection for synthetic test mocks, and cleanly separates API routing, core configuration, domain models, business services, and external gateways.

## 3. Monorepo Conventions & Architecture Patterns

### 3.1 Monorepo Topology
```
the-plan-software/
├── backend/            # Python 3.13+ API (uv, FastAPI, Gemini, Groq, Jev, Firebase)
├── mobile/             # Flutter / Dart client (Android & iOS)
├── web/                # Bun + TypeScript / React client
├── docs/frameworks/    # 11 Communication Framework specifications & Jev catalogs
├── AGENTS.md           # Master Agent Guidelines
└── CLAUDE.md           # Agent configuration & commands
```

### 3.2 Subsystem Responsibilities (`backend/`)
As mandated in `CLAUDE.md` §3.1:
* `app/gateways/gemini.py`: Prompt generation service using Gemini Flash API.
* `app/gateways/groq.py`: Audio multipart upload to Groq Whisper (`whisper-large-v3`).
* `app/gateways/typesafe.py`: Parallel evaluation gateway to TypeSafe AI endpoint (`https://api.typesafe.ai/v1/systemone`).
* `app/services/analytics.py`: Pacing ($WPM$), filler density, and power pause calculations.
* `app/services/scoring.py`: Deterministic scorecards and coaching badges.
* `app/gateways/firestore.py` / `app/services/persistence.py`: Firebase Firestore integration for `theplan-9311e`.

### 3.3 Latency Budget & Cognitive Division of Labor
| Pipeline Stage | Engine / Provider | Latency Target | Role |
| :--- | :--- | :--- | :--- |
| **Generation** | Gemini API (`gemini-1.5-flash` / `gemini-2.0-flash`) | ~600–900 ms (pre-session) | Dynamic scenario generation tailored to role and framework. |
| **Perception** | Groq API (`whisper-large-v3`) | ~250–450 ms (post-speech) | Speech-to-text with word-level timestamps and duration. |
| **Analytics** | Deterministic Service (`analytics.py`) | < 5 ms | $WPM$, pause detection, filler word frequency count. |
| **Judgment** | TypeSafe AI Jev System One (`/v1/systemone`) | ~120–280 ms | Non-generative typed rubric scoring via `choice`, `score`, `noul`. |
| **Coaching** | Deterministic Engine (`scoring.py`) | < 10 ms | Mathematical scoring (0–100), badge assignment, actionable tips. |
| **Total Pipeline** | **End-to-End Feedback Loop** | **< 1.0 s** | **Strict SLA: Never inject autoregressive LLMs into grading path.** |

### 3.4 API & Envelope Contract
All non-2xx responses must strictly return:
```json
{
  "error": {
    "code": "PROVIDER_UNAVAILABLE",
    "message": "Human-readable safe explanation.",
    "retryable": true
  },
  "request_id": "req_uuid_string"
}
```
* HTTP 422: `code: "VALIDATION_ERROR"`, `retryable: false`
* HTTP 404: `code: "NOT_FOUND"`, `retryable: false`
* HTTP 502 / 503 / 504: `code: "PROVIDER_UNAVAILABLE"`, `retryable: true`
* HTTP 500: `code: "INTERNAL_SERVER_ERROR"`, `retryable: false` (Zero stack trace or internal credential leaks).

### 3.5 The Balanced Impact Rule
Defined across `CLAUDE.md` and `docs/frameworks/star.md` (and related framework files):
* Evaluation rubrics must NEVER penalize responses solely because they lack numerical metrics.
* Both **quantified metric impact** (e.g., "reduced latency by 65%") and **meaningful qualitative/operational impact** (e.g., "unblocked mobile team release and prevented client churn") receive **full credit (1.0 weight / 100%)**.

   - Update `pyproject.toml` with the proposed dependencies, ruff, and pytest configurations.

   - Run `uv run ruff check .` to verify toolchain responsiveness.
2. **Step 2: Core & Gateway Infrastructure**
   - Implement `app/core/config.py` with `pydantic-settings`.
   - Implement standardized error envelope models and global exception handlers in `app/core/handlers.py`.
   - Implement abstract gateway protocols in `app/gateways/base.py` and concrete clients (`gemini.py`, `groq.py`, `typesafe.py`, `firestore.py`).
3. **Step 3: Services & Framework Engine**
   - Implement `app/services/analytics.py` (WPM, filler words, pauses).
   - Implement `app/services/scoring.py` with the 0-100 composite formula, badge triggers, and Balanced Impact Rule.

   - Implement `POST /api/v1/scenarios/generate`, `POST /api/v1/sessions/evaluate`, `GET /api/v1/sessions`, and `GET /api/v1/health`.
   - Assemble `app/main.py` with lifespan, CORS, and route aggregation.
5. **Step 5: Automated Testing & Synthetic Verification**
   - Build synthetic fixtures in `tests/conftest.py` overriding gateway dependencies.
   - Execute `uv run pytest` (target: 100% pass without network calls).
   - Execute `uv run ruff check .` and `uv run ruff format --check .` (target: 0 errors).
